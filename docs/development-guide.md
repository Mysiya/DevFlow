# DevFlow AI 本地开发指南

本文描述从零实现的 v0.18 项目：已有五阶段基础闭环、本地中文混合检索、分项同步、签名 Webhook 队列、真实回答人工评审、同源 Prompt 对照、固定评估样本集与任务 Skill，并新增手机界面与安卓客户端工程。源码已按用户要求上传到 Mysiya/DevFlow；当前电脑知识库和源码快照仍是独立的本地来源，与远程 Git 提交分别管理。

## 手机客户端与外网部署（v0.18）

手机界面使用底部导航，保留原来的任务、仓库、知识、记录、代码、审批和评测功能。安卓工程位于 mobile/android，采用原生 HTTPS 连接页和 WebView 工作台；当前 APK 直接连接预设服务器，确认服务开启登录后进入工作台，切换服务器时才填写新地址。手机与电脑需要连接同一服务才能共享记录，关闭客户端不会取消服务器任务。JSON 导出使用系统文件选择器，模型密钥只留在服务端。

最新安卓工程为 0.18.1，安装包位于 artifacts/mobile/DevFlow-0.18.1-debug.apk，也可从网页设置中的“下载安卓版 APK”取得，支持安卓 8.0 及以上。默认读取 mobile/service.json 预设地址，第一次打开直接连接登录页，后续保留会话，无需填写服务地址，账号和模型密钥不写入 APK。SDK 许可已明确同意，手机实机验收尚未完成；服务器启动、认证与外网检查单独记录，不能把 APK 构建当作后台上线。

当前 HTTPS 服务为 https://preview-ff00a4ca69754797.up.railway.app，已完成登录、Worker、源码同步与 APK 下载检查，DeepSeek 认证及模型列表读取通过。使用云端独立 SQLite 和关键词检索，本机历史记录与向量库未迁移。首次登录使用交付的 admin 账号和独立密码，密码只保存在私有交付文件；本次部署没有新增模型分析。维护与 VM 生命周期限制见 infra/cloud/README.md。

compose.mobile.yaml 与 infra/mobile/Caddyfile 提供 HTTPS 部署配置，强制启用账号认证和 Secure Cookie。外网使用需要实际服务器、域名、有效证书和已运行的 API/Worker；现有电脑的回环地址不能直接在外出手机上访问。新的 PostgreSQL 环境不会自动带入本地 SQLite 数据，需要按目标服务器单独迁移。编译和部署说明见 docs/mobile-app.md。

离线提示仅缓存公共提示页与图标，不缓存原回答、源码、API/SSE 或提交内容，也不自动补发问题。API 对成功、错误和 SSE 响应统一设置 private/no-store，流式事件继续逐条发送。安卓 SDK 首次下载和许可接受需要明确同意；源码工程、前端构建和接口核验不能替代 APK 编译、签名、实机登录与外网部署验收。

## 仓库同步与分项时间

连接与配置页展示同步状态、最近完整同步、仓库/Issues/PR/Actions/README 的各自时间。手动同步刷新所有列表，ETag 条件请求复用未变化的响应。事件只更新受影响的列表，所以分项时间可能不同；最近一次事件刷新不代表全仓库数据已更新。列表仍限定为最多 100 条开放 Issues（分页包含 PR）、100 个开放 PR 和 30 次 Actions。README 固定到当前读取的默认分支 SHA。代码工作区的 Git 快照仍需单独同步。

## Webhook 接收与后台刷新

GITHUB_WEBHOOK_ENABLED 默认 false。启用需要 live 模式、独立至少 32 字符 GITHUB_WEBHOOK_SECRET、GITHUB_WEBHOOK_REPOSITORY_IDS 本地仓库 ID 白名单，并先手动同步记录 GitHub 数字 ID。API 和 Worker 必须共享配置并一起重启。接收路径 /api/webhooks/github，原始正文经过 HMAC-SHA256 验签后，还核对仓库名称、数字 ID 和白名单。浏览器 Cookie 或 MCP Token 不能代替事件签名。

issues 事件刷新开放 Issues；pull_request 同时刷新 PR 和 Issues；workflow_run 刷新 Actions；默认分支 push 更新仓库、分支与 README。只支持明确列出的 action，ping、非默认分支 push 和未知事件记录为忽略。事件正文不会直接成为快照，独立 Worker 重新读取 GitHub 当前状态，并校验数字 ID。因此延迟事件不会覆盖为旧正文，也不能借正文中的 URL 指向其他服务。事件不发起模型分析、不执行脚本或写 GitHub。

## 重复事件、失败与恢复

只保存投递 UUID、正文 SHA-256、事件/action、仓库绑定、范围和状态，不保存原始正文或密钥。重复投递返回原状态；相同 UUID 的不同正文或事件拒绝。API 先持久化再返回 202，队列在重启后仍保留。手动和事件刷新共享仓库租约，过期 Worker 不能覆盖新快照；读取中断可重新领取，最多 3 次。读取失败保留原快照，编辑者可重试已接收的失败任务，达到上限后可手动同步。GitHub 未投递成功的事件需要远程重新投递或手动对账，系统没有自动定时完整同步。

## 当前 Webhook 连接边界

签名接收、重复防护、仓库/权限隔离、后台进程和重启恢复已在临时数据库及受控 GitHub 响应中验证。当前真实仓库 Webhook 仍未启用，没有注册到 GitHub，也没有配置公网入口。回环地址不能收到 GitHub 推送，真实联调需要可信 HTTPS 地址、独立入口反向代理和部署权限配置。开发容量为 1 MB 未压缩请求、100 个待处理事件、10000 条历史记录；组织/App 事件、仓库重命名迁移与全仓文档采集仍待实现。

## 启动后端

在项目根目录打开 PowerShell，运行 scripts/start-backend.ps1。后端使用 Python 3.12、FastAPI 与 SQLAlchemy，监听 http://127.0.0.1:8000。也可以进入 backend 目录，用虚拟环境 Python 运行 uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload。

backend/.env 保存配置。DEVFLOW_MODE=live 时读取真实 GitHub 数据并调用模型。LLM_BASE_URL=https://api.deepseek.com，LLM_MODEL=deepseek-v4-pro，LLM_MAX_TOKENS=4096，LLM_REASONING_EFFORT=none。模型密钥只放本地 .env，前端不能读取。更改配置后需要重启后端和 Worker。

## 启动前端

在另一个终端从项目根目录运行 scripts/start-frontend.ps1，或者进入 frontend 后运行 npm run dev。Next.js 页面位于 http://127.0.0.1:3000，通过同源代理访问 FastAPI。

## 知识检索与证据

项目知识页支持导入 Markdown、按标题切分、BM25 检索和带行号的片段引用。同一路径重新导入会更新文档。手动导入的来源标为“本地导入”，和 GitHub 同步文档区分。当前本机运行中文 CPU Embedding 与 Milvus Lite，可使用 BM25 和向量混合召回。远程重排仍未配置或实机验证。

向量召回需要单独配置 Embedding 服务与 Milvus，建立索引成功后才能启用混合检索。混合召回通过 RRF 合并 BM25 和向量排名，重排是可选步骤。索引只在当前文档版本写入成功后激活；文档改变会使旧索引过期。

## 离线中文向量模型

独立 .vector-venv 安装 backend/requirements-vector.lock.txt。第一次运行 scripts/prepare-vector-model.py 下载 FastEmbed 支持的公开 BAAI/bge-small-zh-v1.5 优化 ONNX 权重，约 90 MB，输出 512 维。只下载公开文件，不发送仓库内容或应用密钥。模型与 SHA-256 清单保存在 backend/data/vector-models；清单绑定权重和切窗算法，API 模型名含内容指纹。运行时验证权重，只用本地文件及 CPU，不联网下载。

较长文本按 350 字符、70 字符重叠的窗口切分，取向量均值并归一化，覆盖文本尾部。每次最多 32 条、每条 6000 字符；窗口均值是近似表示。检索得分表示相对排序，不是结论置信度；无关问题也可能得到最近邻，需核对引用内容。

## 启动向量服务

另开两个终端从根目录运行 scripts/start-local-embedding.ps1 和 scripts/start-milvus-lite.ps1。服务固定监听 127.0.0.1:8001 与 127.0.0.1:19530。Embedding 接口使用独立至少 32 字符的 EMBEDDING_API_KEY，与 DeepSeek/GitHub 密钥分开；浏览器不能直接调用它。本地设置 EMBEDDING_LOCAL=true、EMBEDDING_BASE_URL=http://127.0.0.1:8001/v1、EMBEDDING_DIMENSIONS=512、EMBEDDING_MODEL 为准备脚本输出的版本名，RETRIEVAL_BACKEND=milvus、MILVUS_DEPLOYMENT=lite。

Milvus Lite 3.2.1 已在本机 Windows 上运行，无需 Docker。数据保存在 backend/data/milvus-lite，重启使用同一目录。启动脚本以一个 RPC 工作线程串行执行，避免 Lite 并发写入限制。Lite 没有身份认证或 TLS，只适合回环地址上的本机开发。Standalone、PostgreSQL 和容器路线仍待实机验证，当前 Compose 镜像不包含本地向量环境。

## 连接检查与索引重建

更改配置后重启 API 与 Worker。在项目知识页点击“检查向量连接”确认本地模型版本及 Milvus 在线，再点击“建立向量索引”。已保存索引就绪与服务当前在线是两项状态；服务关闭时索引记录仍保留。重启同一数据目录后可继续查询。文档或模型改变需重建索引，相同模型的未变片段复用缓存；仓库 ID 和生成批次共同限定向量查询范围。

混合检索实验台遇到服务中断明确报错。Agent 的只读 search_knowledge 工具会记录降级警告并以 BM25 继续，证据保留实际召回方式，不能将关键词结果标为向量结果。

## 历史周报的来源边界

周报入库后，每个片段都会带 source_scope=historical_analysis 和可能过时的提示；即使截取片段没有包含周报开头，也保留该提示。模型工具将提示写入证据和缺口，不能用旧报告覆盖当前源码或已批准记忆。指南作为项目文档，与历史分析摘要分开标注；更新指南不会改写旧运行保存的证据版本。

## 分析、记录与草稿

工作台支持智能问答、Issue 分诊、PR 风险审查、CI 排障、文档与源码分析及动态 LangGraph 协作检查。LLM Planner 生成有任务预算的依赖图；后端校验任务、目标范围和 DAG，再按并发限制运行。依赖结果和证据传给后续节点，失败依赖跳过，最多补查一次并保留首轮结果。模型只能调用注册的只读工具，工具参数和仓库范围由后端校验。结论保存证据标识、来源和提交 SHA，不能引用不存在的证据。

SSE 推送工具与 Agent 进度。分析结果、执行轨迹、会话摘要与评论草稿保存在本地 SQLite，重启后仍可查看。草稿默认仅本地保存；人工审批、仓库权限和显式 GitHub 评论发布已实现，发布开关默认关闭，模型无权调用写工具。

## SSE 生命周期

后端 /api/chat/stream 先创建 AgentRun 和会话记录。emit 先将事件保存到数据库，再放入 asyncio.Queue，由 stream 以 SSE 发送；每 15 秒空闲发送 heartbeat。execute 完成时保存结果和 completed 状态，异常时保存 failed，随后发送对应结束事件。事件已持久化不代表客户端已接收。

v0.5 页面先通过 /api/chat/runs 保存后台任务，再用 GET /api/repositories/{repository_id}/runs/{run_id}/events?after=N 订阅已保存事件。断开连接只关闭订阅，不取消独立 Worker；客户端按已处理的事件编号重连。点击“暂离工作台”或刷新页面后，可以从运行记录重新查看进度。显式点击“停止”才发送数据库停止请求：排队任务立即取消，正在执行的任务由 Worker 确认后取消并释放工具连接。

API 重启保留租约仍有效的后台运行。Worker 采用独立进程和数据库队列，默认每个 Worker 同时执行 2 个运行；心跳租约默认 30 秒。Worker 退出或租约过期后保留进度并标为 interrupted，不自动重复调用模型。协作检查支持手动从任务检查点继续；其他任务和旧版本记录需重新发起分析。旧 POST /api/chat/stream 接口仍保留断连取消行为，当前页面不再使用。

## 任务检查点恢复

协作检查在 Planner 计划和每个任务终态写入 SQL 检查点后再宣布完成。运行记录中的“从断点继续”沿用原计划、源码提交、文档版本、已保存结果和任务预算。依赖节点能继续引用前序任务的证据；已保存的汇总结果直接恢复输出。原运行 ID 保持不变，事件序号连续追加。

任务 completed、partial、failed、skipped 是已保存的终态，不自动重跑。没有终态记录的任务重试，进行中的模型请求和工具步骤不做内部续接，因此中断前未保存的响应可能再次请求。一次补查机会不因恢复重置。默认恢复最多 3 次，实际取原运行策略与当前 MAX_RESUME_ATTEMPTS 配置的较小值。恢复入口还会检查旧源码是否可读取，以及已分析 PR 的当前 head SHA；模式或模型配置变化、旧源码不可读取、PR 提交变化时拒绝恢复，需重新分析。

文档库更新或归档后，恢复仍按原运行的片段版本检索，旧快照使用 BM25 并提示来源。恢复结论属于原版本的分析，不能当作实时 GitHub 状态。当前恢复为应用层任务检查点，后台 SQL 队列通过条件更新和执行令牌阻止重复领取、旧 Worker 写入；尚未接入 LangGraph 原生 Checkpointer。默认本地模式不验证身份，可以启用登录及仓库角色；PostgreSQL 与多机器共享代码缓存未实机验证。

## 项目记忆与人工批准

“记忆与审批”允许人工录入项目约定，或从已完成运行提取候选，附当前仓库的来源证据。候选、拒绝或归档记忆不进入新分析。审核者批准后，search_memories 工具通过 BM25 返回最多 3 条相关内容，引用标明记忆 ID 和批准版本。检索实验台可以直接检查批准前后是否命中。

新任务入队时固定最近 50 条已批准记忆；工作流检查点保存同一份快照，后续修改、拒绝或归档不改变已提交任务的原引用，恢复也沿用原版本。修改任意内容后状态回到候选，必须重新批准。当前没有自动超长对话压缩和记忆向量索引。

## 账号权限、草稿与发布

默认 AUTH_ENABLED=false，界面显示“本地模式，未启用登录”，各操作记为未验证的本地管理员。启用登录前设置至少 12 位 BOOTSTRAP_ADMIN_PASSWORD，首次启动创建管理员；已存在管理员时不会重置。密码为带盐 scrypt，服务端会话保存 Token 哈希，12 小时过期。管理员可创建用户并赋予仓库 viewer、editor 或 maintainer 角色；停用用户撤销其会话。真实 HTTPS 部署应启用 AUTH_COOKIE_SECURE。

评论草稿有待提交、待审核、已批准、已拒绝等状态。每次修改或审核推进版本，过期页面的请求被拒绝；修改正文或目标会撤销审批。绑定的 Issue/PR 必须出现在原分析证据中，PR head SHA 在审核和发布前重新读取。

GitHub 发布同时要求真实模式、已启用登录、审核权限、GITHUB_WRITE_ENABLED=true 和具有仓库写权限的 Token。写客户端独立于 Agent 工具，默认未启用；当前本机未实际发布评论。发布领取记录在远程写之前保存，并用正文标记检查重复；超时或中断进入 uncertain，核对入口只能 GET 评论，绝不自动重发。PR 可能在预检后继续变化，需核对远程结果。系统记录记忆、草稿、后台分析及成员授权操作的审计。

## 启动后台 Worker

在第三个 PowerShell 终端运行 scripts/start-worker.ps1，或进入 backend 目录执行虚拟环境 Python 的 -m app.worker。API 与 Worker 必须读取同一 .env 并共享数据库和 backend/data/code。未启动 Worker 时任务保留为排队中。WORKER_CONCURRENCY 默认 2，QUEUE_POLL_SECONDS 默认 0.5，JOB_LEASE_SECONDS 默认 30。排队与运行的任务总量上限为 100。

## 固定版本源码

代码工作区可同步 GitHub 默认分支，或在本地开发环境为当前 DevFlow 项目创建独立 Git 快照。文件列表、行号浏览和源码检索固定到完整 SHA；模型分析在开始时固定版本，后来同步新提交不会改变旧结果的证据。当前源码来源为本地快照，与 GitHub 远程状态分开标注。

v0.10 使用 BM25 排序代码片段，保留标识符原词并拆分驼峰、缩写和下划线名称，也支持路径与中文注释关键词。Python 通过 AST 解析函数、类、嵌套方法和装饰器行段，不导入或执行源码。TypeScript 等其他语言，以及当前 Python 解释器无法解析的源码，只按文本行段切分，明确标注解析回退；不声称理解全部语言的语法。

单片段最多 80 行、6000 字符，长定义分段并保留完整定义行号；超长单行不截断引用，显示遗漏计数。片段按 BM25、路径和 Python 定义匹配排序，去掉过度重叠的命中，分数不是正确率。Agent 的 search_code 工具及源码页面共用同一实现；证据附符号、片段种类、路径、行号和 SHA。查询仍依赖源码词汇，不提供自然语言语义向量检索或自动代码执行。

一次读取最多 400 行，Agent 对明确指定的文件按每段 100 行读取前 400 行，再补充关键词命中；更长文件会显示覆盖缺口。工作区不执行仓库代码或测试。默认排除密钥文件、依赖目录、Android SDK 的 .local 目录与 .gradle 缓存，导入、检索和固定版本回读沿用同一规则。Git 对象保存在 backend/data/code；向量源码检索、PR 分支自动获取和旧对象回收尚未实现。

## 有限源码事实核对

v0.11 以固定 SHA 的合法 Python 源码证据为输入，使用 AST 识别唯一直接全大写数值声明，以及特定结构 BM25 公式的 k1、b。不执行源码，不求值调用或算术表达式。只匹配回答中全大写常量和 k1/k_1/b 的等号、冒号、为/是/等于等有限数值语法，不验证其他自然语言解释、完整程序或运行值。部分函数、语法失败、作用域/文件/版本歧义和无法识别的声明均保持未验证。

v0.12 新增分子乘数与 k1+1、长度常数项与 1-b 的有限数学关系检查。来源绑定固定到引用的 SHA、文件和作用域；根据已识别评分公式计算预期数值，不硬编码参数。支持“分子中的2.2不是k1+1”“分子乘数等于k1+1”“k1+1=2.2”“0.25=1-b”等有限句式，正/否关系都可比对。连等式仅核对支持的关系对；`k1+1=1.2+1`、`1-b=1-0.75` 的算术右项不能截成数值声明，也不执行求值。数值声明与公式关系分别计数，未识别的写法不计入。

直接写字面量、写成参数表达式和数学关系是不同概念。建议、假设、引述、源码写法说明保留未验证，其他语义解释与运行行为仍需人工检查。这不是通用自然语言理解或完整 BM25 实现验证；不能因某些已识别关系一致而认定整段回答正确。对于已识别公式，不同乘数也根据该版本源码判定关系，而不是套用默认乘数。

所有主要回答字段（包括待确认项）参与核对；finding 只使用它引用的源码。否定、假设与修改建议不标为已核对。冲突段落移出正文，finding 的标题或详情冲突时整项移出，保留原回答与原表述，分析建议提示复查；协作子任务冲突传入最终汇总。此时暂停自动生成新的评论草稿，新周报标明冲突并仅使用核对后的摘要。人工编辑的既有批准记忆、草稿和旧周报不回写。

历史运行可点击“核对源码事实”，按保存的原证据生成只读复核预览，不覆盖分析、事件或检查点，不发起模型请求。新运行自动保存有限核对的检查器、输入和来源指纹。即使数值一致，仍需核对证据覆盖范围、上下文和其余解释；不能把检查器的局部结果当作回答整体正确。

## 固定评测与 Ragas

评测与交付页运行 core-v4 的 60 个固定样例：8 条文档/演示分析检查、10 条源码检索检查与 42 条事实核对回归（原数值 16、有限关系与解析边界 26）。文档比较标题关键词和 BM25 的 Precision、Recall、MRR@2；源码比较旧行关键词和新策略的 Top 1、Recall@5、MRR@5，命中须覆盖标准路径的完整标注行段。源码平均指标只含 8 个正例，无匹配和目录隔离单独验证。保存数据集、评分器与实现指纹，旧 core-v1/core-v2/core-v3 历史不改写。这些人工回归样例不是大模型准确率，真实仓库标注集和 Prompt 质量评估尚未完成。

### 真实回答评审

v0.13 的“评测与交付 → 回答评审”展示已完成分析的原文和当时证据。人工逐项标注有证据支持、与证据冲突、证据不足或不作事实判断，必须填写理由；支持和冲突须选取本回答中的证据。允许部分标注，未标注字段不算正确，有限自动检查单独展示，不能替代整段评审。

评审写入新的 answer_reviews 表，maintainer/admin 可以保存，viewer/editor 可以读取。每次保存追加版本，含回答与证据指纹、标注、评审者和当时快照，不改原分析和事件。并发和过期版本受校验；重复同一提交复用记录。回答或证据变化后旧标注从统计中排除，历史版本仍能读取保存时的原文。统计只含最近 30 次已完成运行的最新有效标注，不显示模型准确率。最多显示 20 个历史版本，单次上限为 100 个字段、128 项证据和 40 万字符。

JSON 导出保留当前回答、最新评审和评审时的快照，含有限自动核对及未标注状态，供后续人工整理样本。它不是已完成的真实 gold dataset 或 Prompt A/B，也不会批准草稿、记忆、发布评论或调用额外模型。现有已批准记录和固定回归批次保留。

### Prompt 选择与回答对照

v0.14 工作台输入框可选 baseline-v1（保留原分析指令）或 evidence-first-v2（补充逐字段来源、建议与事实区分）。版本由服务端代码维护，不接受任意 Prompt 正文。只修改最终结构化分析指令，Planner 与工具决策指令不变；协作各专用分析和汇总沿用所选版本，演示模式不使用大模型。

提交时固定版本与模板/模型参数指纹，排队或恢复执行前核对；内容、服务或输出上限等参数变化时停止并提示重新分析。旧任务没有版本绑定时沿用当前基线，不推断它历史使用的 Prompt。新模型回答保存实际系统指令、版本、角色、模型/参数、完整输入与来源指纹，不额外保存完整用户请求正文，密钥不进入这些记录。

评测与交付的回答对照页选择最近 30 次已完成记录中的两次，展示原回答、当时证据、有效人工标注、实际用量与 JSON 导出。对照只读取已有数据，不调用模型。不同问题、源码版本、缺口、检索证据、模型服务/参数或分析协议均不能标为同源 Prompt 对照；版本信息缺失或记录无法核对时说明未知。只对单次 live 源码/知识分析检查同源条件，ChatAgent 与多 Agent 运行可查看历史，但不纳入受控比较。

满足条件只说明比较输入受控，不判断哪个答案更好，不给胜率或准确率，不替代人工 gold 标注和代表性样本评估。旧记录不补造 Prompt 信息，被自动隔离的原回答仍可查看，过期人工标注排除。既有真实记录缺少新版本信息；v0.14 隔离测试使用受控 HTTP 响应验证执行和记录，没有新增实际模型调用。

### 同一份输入提交两版分析

v0.15 在回答对照页新增两版提交。仅真实模式下的编辑者与审核者可创建，支持源码和知识任务。一次读取仓库快照、源码固定 SHA、当前文档片段和批准记忆，在同一事务中创建两次任务，各使用一个固定 Prompt 版本；新会话不加入此前历史。两次任务提交时的来源指纹相同，完成后还要核对实际模型输入和证据，不能仅因同批创建就认定满足受控比较。

提交编号 request_id 在同一仓库内唯一。同一问题、任务和提交者重试返回原组及两次运行 ID，内容改变或其他提交者复用编号会返回冲突。并发重复请求不会增发任务，容量不足会整组回滚；一个组只在事务提交后对 Worker 可见。版本与模型参数绑定沿用 v0.14 校验，不接受任意 Prompt 或其他运行 ID。

创建会调用两次真实模型，费用仍按实际用量和已有单价展示，未知价格不补算。页面显示排队/执行/完成/失败/停止，关闭页面不停止后台任务，停止按钮只请求取消本组未完成任务。已完成回答保持原样，失败或中断不自动补发。最近 20 组可查看，完成的旧组即使不在最近 30 次候选窗口，也按原 ID 读取。viewer 只读，MCP 白名单不增加接口。

v0.15 实际源码联调首次因具体载荷授权不足被自动审批拒绝；本地生成 code_search.py 固定片段、同一个问题、提取事实与两版系统指令的预览后，用户明确批准发送至官方 DeepSeek、最多两次分析。现已完成一组 baseline-v1/evidence-first-v2 的真实 DeepSeek V4 Pro 分析，各调用一次，无追加请求。实际完整输入指纹与批准预览相同，固定 SHA 的引用逐项核对，原回答及 JSON 导出已保存。有限数值与 BM25 关系检查均无冲突，证据优先版的 4 处建议或源码写法说明仍为未判定；没有生成胜者或人工标注。已完成分析共 14 次、232 个字段全部未标注。282 项后端回归及前端构建通过，浏览器交互验收因工具无法启动仍未完成。

### 固定评估样本集

v0.16 新增“评估样本集”。编辑者可以选择已完成的真实两版对照，填写名称与场景说明后保存；每集最多 20 组、12 MB。服务端检查实际完整输入、证据、参数与版本满足对照条件，固定保存原回答、来源与用量。创建、读取和导出没有新模型请求，也不生成标注。提交编号绑定规范化内容与提交者，同一编号重试和并发只保存一份；样本集不可覆盖修改。

统计只使用与固定样本一致的当前有效人工评审，按 Prompt、模型参数、角色和协议分组列示覆盖数及四类标签。未标注不算正确，过期评审排除；来源、回答或版本变化使整组退出当前统计，历史固定内容仍可查看/导出。可从样本集打开具体运行进行评审，即使它已不在最近 30 次候选范围。viewer 只读，editor 可整理样本但不能保存人工评审，审核者继续使用原评审接口；MCP 白名单不扩展。相同输入数量、完成标注数量不是代表性或质量分数，没有胜者和准确率。

Ragas 0.4.3 在根目录独立的 .eval-venv 中安装，与后台依赖分开。页面运行的是非模型 Context Recall 和 Context Precision，阈值 0.5，通过字符串相似度评分 6 条固定文本样例，不测答案忠实度、不发外部模型请求。JSON 样例可导出。子进程不接收用户仓库内容或模型密钥，遥测与在线数据集访问关闭。

## 任务 Skill（v0.17）

工作台输入框的“任务流程”提供四种可重复使用的分析要求：固定源码解释、PR 风险审查、CI 排障、发布前协作检查。选择后自动切换任务类型并显示检查项；PR 和 CI 需要填写明确的 PR 编号或 CI run ID，不从问题猜测目标。输入具体问题后提交，结果显示流程名称、版本与定义指纹。切换任务、仓库或使用快捷分析会清除已选流程，避免带入其他任务。

这些流程由 `backend/skills/` 的固定 JSON 注册表维护，包含适用角色、只读工具范围、检查项和分析指令；不接受上传脚本、任意路径、任意工具或远程安装。live 下流程要求进入专用分析系统指令，协作流程同时作用于 Planner、专用角色和 Synthesis，仍受原有计划预算、DAG、证据引用和仓库权限校验。演示模式继续使用规则引擎，不表示已经验证模型能完成全部检查项。

任务提交时保存 Skill ID、版本和完整定义指纹，排队/恢复执行前重新核对；定义或模型参数变化时停止，提示重新分析，不用新指令继续旧任务。领取后在内存保留该定义，检索、规划、专用分析与汇总使用同一版本，执行中更新文件不会替换当前指令。实际模型上下文在发送前固定，结果不接受模型伪造版本字段。未选流程的旧 Prompt 字符串与上下文格式保持兼容，历史真实对照和固定样本不补造 Skill。不同 Skill 或版本不能混作同源 Prompt 比较；评估覆盖统计也按 Skill 分组。

查看目录和流程要求不会调用模型；在 live 模式提交分析会使用已配置模型，协作流程可能涉及多次请求。检查项只是要求，是否完成应核对结果和证据，缺证必须保留。当前采用 HTTP 模拟响应、演示 Worker 与恢复测试验证接入，本轮没有新增真实模型调用；代表性真实问题与人工质量评估仍待完成。

## 耗时和实际用量

从 v0.7 开始，每次执行或恢复记录耗时、模型请求状态和供应商返回的 Token，用量属于该运行，执行时间不包括排队。历史记录和中断请求没有返回的用量显示未知。只存模型名称、时间、状态、用量和价格，不额外存请求正文。LLM_INPUT_PRICE_PER_MILLION、LLM_OUTPUT_PRICE_PER_MILLION、LLM_CACHED_INPUT_PRICE_PER_MILLION 可手动配置每百万 Token 的费用；默认均未配置，费用未知。缓存命中需要单独的缓存价格。价格固定到每次请求，估算不能当作账单。

## 已保存分析周报

周报按北京时间周一至周日，依据本地运行创建时间汇总当前模式的已完成分析，最多 100 条，保留来源运行和证据。它不代表 GitHub 全量活动，也不代表所有模型结论已被审核。重复生成相同内容复用记录；审核者确认后可存入本地知识库，没有外部发布或定时发送。

## MCP 只读工具

官方 MCP Python SDK 通过 stdio 提供 repository_snapshot、search_knowledge、search_approved_memories、saved_run、read_code、weekly_reports 六个工具。启动 scripts/start-mcp.ps1 前，先在本地配置独立的至少 32 字符 MCP_ACCESS_TOKEN 与 MCP_REPOSITORY_IDS 仓库 ID 白名单，并重启 API。默认均为空。MCP 只访问回环 API，只能读取授权仓库的白名单接口，不允许创建、审批、发布或读取候选记忆及草稿。错误 Token 不会获得默认本地管理员权限。协议测试使用独立临时库，没有启用实际仓库的外部客户端访问。
